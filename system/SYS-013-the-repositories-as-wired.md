# SYS-013 — The repositories, as wired

> **Summary:** Every repository of the numengames organisation, as data in
> `system/repos.yaml`: what it is and is not, its project, owner, state and
> licence, and what reads it; and the copies between them still standing.
> **Epistemic:** Where each thing of the house lives today, and which things
> still live in two places.
> **Pragmatic:** Before changing something another repository reads, know
> who reads it; before copying something, find its original; before adding or
> retiring a repository, change the data first.
> **Audience:** Agents · Oracles

> **A system document is a reference manual, not a plan.** Pieces that do not
> exist yet are listed with the state `to-create`; nothing here says they run
> until they do.

---

## 1. Scope

The repositories of the numengames organisation on GitHub and the lines
between them: who reads what from whom. The rule they follow is `ADR-068`;
how each site is built and deployed is in each repository's own README.
Private repositories outside the organisation's public list (the workspace
template nwos-deploy generates from) are named where they are read, not
described.

---

## 2. How it works

### The repositories

The map is data. `system/repos.yaml` holds one entry per repository, keyed by
GitHub's numeric id (a rename keeps it): its name and the names it had, what
it is, what it is not, its project and Kanban board, its human owner, its
state, GitHub's description and homepage, its licence regime, and what it
reads from other repositories. The two tables below are generated from it by
`machine/tools/repos-table.mjs`; a test fails when they differ from the data,
so a fact is changed in the data and the tables follow.

A state is one of: `active`; `deprecated` (still has readers, and is being
merged into another repository); `to-archive` (its owner has decided, and
something named in its entry has to happen first); `archived` (GitHub's
archived flag is set); `to-create` (it does not exist yet, and has no id).

### Joining and leaving

A new repository is born from the template `numengames/numengames-repo-template`,
never from an empty folder, and gets its entry in `system/repos.yaml` first:
state `to-create`, `id: null`, with what it is, what it is not, its owner and
its project. Once GitHub has created it, the id and the state `active` are
written in the same pull request that this document changes in.

A repository with no commits and no deploy in 90 days is brought to its owner,
who decides whether it is archived. If yes, its state becomes `to-archive` and,
when GitHub's archived flag is set, `archived`; if not, the reason stays in its
entry. Nobody archives a repository for its owner, and an archived repository
is never deleted from the data: its id and its names keep resolving.

No check reads GitHub's activity: the 90 days are noticed by whoever
looks at the listing, and the owner is told.

### How a shared thing flows

An original lives in one repository. Every other repository either **links**
to it (a page address, a published version it reads) or **installs** it (a
versioned package, a reusable workflow pinned by commit). Nothing is copied
by hand. Where a link reads the original by its path in git rather than by a
published address, a move of that file breaks the reader without any check
in the archive seeing it.

## 3. How to verify it

```
$ node machine/tools/repos-table.mjs --check
$ curl -s 'https://api.github.com/orgs/numengames/repos?per_page=100&type=all' \
    | grep -E '"(id|name|visibility|archived|description|homepage)"'
```

The first compares the tables with `system/repos.yaml`. The second is the
source of the id, name, archived flag, description and homepage of every
entry that exists. For the licence column, the repository's `LICENSE`,
README and `REUSE.toml`. For the debt table: compare the `version:` line of
each legal copy with `legal/` here, and the `uses:` lines of each site's
workflows with this archive's.
